# 情报引擎生产级产品规格

## 产品定位

本项目是一个面向 AI 与 Amazon 卖家运营的公开信源情报平台，不是新闻聚合器，也不是临场搜索 Agent。

系统目标是把大量公开信源转化为可检索、可解释、可分发、可回测的中文情报资产：

```text
公开信源
  -> 抓取
  -> 标准化
  -> 低成本预筛
  -> LLM 语义评分 / 摘要 / 翻译
  -> 确定性策略打分
  -> 事件聚类
  -> 日报 / RSS / API / Skill / Web
```

生产标准从第一天执行：

- 信源按数据库注册和状态管理，不把 YAML 当长期运行源。
- 抓取按任务调度和 Worker 执行，不顺序扫全量信源。
- LLM 只输出结构化中间量，不直接决定是否精选。
- 策略、阈值、公式、Prompt 必须版本化。
- 同一事件必须聚类，多来源报道折叠。
- 公开 API 和内部策略字段隔离。
- 所有输出以中文情报资产为核心。

## 频道

### AI 情报频道

面向 AI 产品、开发者工具、研究和商业化观察。

分类：

- `model_release`：模型发布、能力升级、API 能力变化。
- `product_update`：产品发布、功能更新、体验变化。
- `agent_tool`：Codex、Claude Code、Cursor、OpenCode、Cline、工作流和开发者 Agent。
- `research_paper`：论文、研究观点、工程方法、可复现成果。
- `industry_event`：公司动作、融资、政策、基础设施和生态变化。
- `commercial_signal`：AI 工具、套利、分发、价格和商业化案例。
- `ops_technique`：技巧、观点、使用方法和工作流改进。

### Amazon 卖家情报频道

面向亚马逊卖家、跨境电商运营、品牌方和服务商。

分类：

- `policy`：平台政策、官方规则和合规变化。
- `account_health`：封号、KYC、绩效、评论滥用、Listing 下架风险。
- `fba_logistics`：FBA、AWD、库存配置、配送、仓储、退货。
- `ads_ppc`：Sponsored Ads、DSP、广告位、竞价、广告活动变化。
- `listing_seo`：标题、五点、图片、A+、排名、搜索变化。
- `fees_margin`：佣金、仓储费、低库存费、优惠券、折扣经济账。
- `product_research`：需求信号、类目变化、竞品动向、季节机会。
- `tools`：卖家工具、插件、数据分析、评论挖掘、调价工具。
- `compliance_trade`：税务、海关、贸易政策、认证、进出口风险。

Amazon 频道按卖家运营影响评分，不按泛新闻热度评分。

## 用户结果

用户应该能稳定获得：

```text
过去 24 小时 AI 圈有什么重要变化？
过去 24 小时亚马逊卖家圈有什么风险和机会？
过去 7 天亚马逊账号风控有什么消息？
过去 7 天 FBA / 广告 / 平台政策有什么需要注意？
给我一份 2026-06-17 的跨境卖家日报。
这个政策变化对美国站家居卖家有什么影响？
过去 30 天 AI Agent 工具有什么趋势？
```

系统返回结构化中文情报：

```text
标题
一句话摘要
事件背景
影响对象
影响区域 / marketplace
影响程度
紧急程度
建议动作
来源
原文链接
相关来源
入选理由
事件簇
```

## Web 产品形态

Web 端采用三模式工作台：

- `Reader Mode`：公共端，面向普通用户阅读情报、日报、RSS、信源墙和提交反馈。
- `Ops Mode`：运营端，面向信源、任务、健康、质量、审核、日报发布、反馈和权限管理。
- `Lab Mode`：策略端，面向策略版本和评估运行，不承诺完整后端回测引擎。

Reader Mode 以“今日 Brief + 事件簇 + 日报”为主，展示单位默认是事件而不是裸条目。Ops Mode 以异常处理和运营效率为主，视觉优先级低于可读性。Lab Mode 复用已有 `StrategyVersion` 和 `EvaluationRun` 数据契约，不在前端模拟不存在的指标。

## 产品原则

### 信源比信息重要

信源是系统资产。每个信源必须有类型、等级、权重、抓取策略、运行状态和噪声统计。

信源等级：

- `T1`：官方一手信息，如官方博客、官方文档、官方公告、官方 API。
- `T1.5`：官方社交账号、官方论坛、官方 changelog，速度快但噪声更高。
- `T2`：高可信媒体、研究机构、专家博客、行业数据库。
- `T3`：KOL、论坛、服务商博客、综合资讯站，主要用于补充和早期信号。

### 脚本 / Skill / Agent 分工

系统采用：

```text
脚本和服务 > Skill > Agent
```

- 脚本和服务：抓取、调度、解析、去重、入库、公式打分、阈值判断、RSS/API 输出。
- Skill：受控查询、日报读取、精选读取、Markdown 默认输出。
- Agent：开放式分析、策略复盘、专题报告、信源建议、卖家行动推演。

Agent 不负责高频抓取、最终评分、阈值判断或数据库写入。

### LLM 只做中间量

LLM 输出：

- 相关性。
- 影响程度。
- 新颖性。
- 行动价值。
- 可信度。
- 分类。
- 摘要。
- 翻译。
- 入选理由候选。

确定性代码负责：

- 来源权重。
- freshness 权重。
- 类别阈值。
- 重复惩罚。
- Amazon 运营影响权重。
- 最终分。
- 是否精选。

### 策略必须可治理

评分和精选策略必须支持：

- 策略版本。
- Prompt 版本。
- 模型版本。
- 阈值版本。
- 历史样本回测。
- 新旧策略对比。
- 人类反馈。
- 成本统计。
- 回滚。

### 事件优先于条目

公开输出默认展示事件簇，而不是裸条目。同一事件的官方源、社交源、媒体源和 KOL 源应聚合。

主条选择原则：

```text
官方公告 / 官网 > 官方社交账号 > 权威媒体 / 研究机构 > KOL / 综合站
```

## 核心能力

### 信源运行平台

- 数据库注册信源。
- 记录信源运行状态。
- 按优先级、频率、失败退避调度。
- 支持 RSS、HTML、公开 API、GitHub、官方文档、第三方数据接口适配器。
- 支持信源暂停、降频、隐藏、提报和审核。

### 情报处理流水线

```text
fetch
  -> normalize
  -> prefilter
  -> score
  -> translate
  -> rank
  -> select
  -> cluster
  -> publish
```

每个阶段必须可重试、可观测、可统计。

### 策略实验平台

- 管理策略版本。
- 对比新旧策略。
- 回放历史样本。
- 标注误选和漏选。
- 统计精选率、噪声率、成本、类别分布、来源贡献。

### 多端分发

公开输出：

- Web Reader Mode。
- RSS。
- REST API。
- Agent Skill。
- 日报。

内部输出：

- Ops Mode 信源、任务、健康、质量、审核、日报发布和反馈工作区。
- Lab Mode 策略版本和评估运行工作区。

## 生产技术基线

- Python 3.12+。
- FastAPI + Pydantic v2。
- PostgreSQL 16+。
- SQLAlchemy 2。
- Alembic。
- pgvector。
- httpx。
- feedparser。
- trafilatura。
- Playwright / Crawl4AI adapter 仅用于少数需要浏览器渲染的高价值公开页面。
- Postgres job table + `FOR UPDATE SKIP LOCKED` 起步。
- Docker Compose 起步，后续可迁移到独立 worker 平台。

## 安全边界

系统只处理公开信源和明确授权 API。

不得：

- 自动登录 ChatGPT、Claude、OpenAI、Amazon Seller Central 或其他账号。
- 读取邮箱验证码、OTP、Cookie、私有会话或私有卖家通知。
- 抓取需要登录的 Seller Central 页面。
- 自动点击授权页面。
- 绕过网站限制、验证码、付费墙或访问控制。
- 复制 AIHOT 的品牌、页面文案、数据源库或视觉设计。

如果未来接入私有账号数据，只能通过官方 OAuth/API，例如 Amazon SP-API，并单独做权限、审计和数据隔离设计。
