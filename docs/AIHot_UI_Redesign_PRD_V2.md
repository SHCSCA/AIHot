# AIHot UI Redesign PRD V2.1

**状态：** 已按 2026-06-17 代码实现校准
**设计方向：** 克制的 Liquid Intelligence Glass 情报工作台
**目标：** 让公共阅读、后台运营、策略评估处在同一个清晰产品层级中，同时保留高可读性和可维护性。

## 1. 产品模式

Web 端不再按“前台 + 后台表格”理解，而是三种工作模式：

- `Reader Mode`：公共端，读今日 Brief、精选/全部情报、日报、RSS、信源墙、反馈。
- `Ops Mode`：后台运营端，处理信源、任务、健康、质量、审核、日报发布、反馈和权限。
- `Lab Mode`：策略端，复用现有策略版本和评估运行能力。

模式边界必须在导航、页面标题、信息密度和权限上同时体现。Reader 负责理解情报，Ops 负责处理异常，Lab 负责策略校准。

## 2. Liquid Glass 设计原则

玻璃质感服务信息层级，不作为装饰目标。

可使用玻璃材质的位置：

- 全局导航和移动端底部导航。
- Cmd+K、登录门、浮层、轻量提示。
- Reader 首页 Brief、事件决策面板、筛选栏 active 状态。
- 公开信源墙的 dossier 卡片。

默认不使用重玻璃的位置：

- 后台密集表格。
- 日报正文和长摘要。
- 表单输入区。
- 错误、加载、空状态中的关键说明文本。

## 3. 主题和颜色

深浅色主题都必须满足同一信息层级：

- 背景：低对比氛围层，不抢正文。
- Surface：按 `subtle`、`panel`、`floating` 三层区分。
- 文本：正文优先可读，弱信息用 secondary，不用低透明度正文制造层级。
- Accent：AI 和 Amazon 频道可以有视觉差异，但不能让页面变成单一色相主题。
- 状态色：成功、警告、错误和处理中必须独立于频道色。

深色主题重点避免“全深蓝一片”；浅色主题重点避免“灰字玻璃上不可读”。

## 4. 动效与交互

动效应表现“液态玻璃的响应”，不是持续炫技。

已采用或推荐采用：

- 筛选胶囊：active 背板滑动，保持 `aria-pressed`。
- 情报卡：轻微 hover lift，决策面板用稳定色块承载“入选依据 / 下一步”。
- 刷新状态：时间线 loading chip 和轻扫描感。
- Cmd+K：玻璃浮层、选中项光标、键盘闭环。
- 登录门：ambient scan、轨道符号、提交状态联动。
- 移动端：筛选栏横向滚动，事件摘要和分数徽章避免遮挡底部导航。

全局要求：

- 所有非必要动效在 `prefers-reduced-motion` 下关闭或变为瞬时状态。
- 动画不得改变关键内容尺寸，避免虚拟列表跳动。
- hover 效果不能成为唯一可见状态，键盘 focus 必须有独立样式。

## 5. Reader Mode

Reader 首页目标是让用户在首屏理解“过去 24 小时有什么重要变化”。

关键结构：

- 今日 Brief：突出 Top 事件、频道、窗口范围、信源状态。
- 情报流：突出标题、摘要、精选分、来源数、成员数、入选依据、下一步。
- 展开详情：显示主来源、相关来源、证据链和成员条目。
- 日报：正文宽度控制在 `68-76ch`，归档入口不能挤压正文。
- 信源墙：展示等级、类型、状态、权重、噪声、抓取间隔和贡献数，让用户理解信源可信度。

## 6. Ops Mode

Ops Mode 优先效率，不追求强视觉冲击。

关键结构：

- Dashboard：像运营 Inbox，优先显示健康告警、失败任务、待审核事件和日报状态。
- Sources：突出启停、健康、权重、抓取方式、状态和噪声。
- Jobs：突出失败原因、重试入口、锁定状态。
- Quality：把漏斗做成可读数据流，tab 使用真实 `role=tab` 和 `aria-selected`。
- Review / Publish / Feedback：操作区和只读证据区分清楚，风险操作有 loading/error/success 状态。

## 7. Lab Mode

Lab Mode 初版只复用现有后端能力：

- Strategies：展示版本、阈值、模型配置和激活状态。
- Evaluations：展示运行状态、指标、反馈分布和来源贡献。

不得在前端 mock 完整回测引擎、未返回的指标字段或不存在的数据契约。

## 8. 验收标准

- 深色和浅色主题均可读。
- 玻璃效果不过度模糊、不过度发光。
- 后台表格、日报正文、表单输入不因玻璃效果降低可读性。
- 移动端无全局横向滚动。
- Cmd+K、筛选、展开详情、后台 tab 均可键盘操作。
- 控制台无运行时 error，资源无 404。
- `npm test -- --run` 和 `npm run build` 通过。
